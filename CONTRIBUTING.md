# Contributing

Search existing issues and pull requests before opening a new one. Discuss non-trivial changes before investing substantial implementation time.

## Pull Requests

1. Create a descriptive branch from `main`.
2. Keep each pull request focused on one coherent change.
3. Run `s/lint`, `s/scan`, and `s/test` before pushing.
4. Update relevant specifications, documentation, and tests with behaviour changes.
5. Explain the change, rationale, and any remaining risks in the pull request description.
